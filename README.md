# Сигнал — AI Product Feedback Manager

Локальный MVP для анализа продуктовой обратной связи. Python 3.9+ и SQLite, без сторонних runtime-зависимостей. Русский веб-интерфейс на HTML/CSS/JavaScript. Все ресурсы локальные, нет CDN, аналитических пикселей и внешних LLM-вызовов.

Реализованы инкрементальный read-only коннектор с checkpoint/overlap, очередь с retry/DLQ, маскирование, контракты внутренних Qwen/ASR/VL, реестр с подтверждениями и версиями, проверка совпадения потребностей, статистика, редкие старые пожелания, решения PO, редактирование/split/merge, одобренное создание/связывание задачи, идемпотентность, status sync, ACL, аудит и TTL.

Это работающая основа для пилота. Корпоративные интеграции не проверены без доступа к системам. Независимая разметка, baseline, KPI качества, промышленная ИБ и go/no-go не подменяются синтетическим демо: см. [готовность к приёмке](docs/acceptance.md).

## Быстрый запуск

```sh
python3 -m feedback_manager --db data/demo.db demo
python3 -m feedback_manager --db data/demo.db serve
```

Откройте <http://127.0.0.1:8080>. Команда `demo` создаёт 27 синтетических обращений, 8 тем и пользователей `po`, `po2`, `admin`, `source`. Случайные пароли выводятся **при первом создании** и сохраняются в `data/demo-credentials.json` с правами 0600. БД и пароли исключены из Git. Если пользователи уже созданы и пароль потерян:

```sh
python3 -m feedback_manager --db data/demo.db password po
```

`po` видит оба продукта, `po2` — только аналитику. `admin` видит операционный журнал, но не получает доступа к содержимому тем. `source` — сервисный аккаунт для ingestion, не PO.

По умолчанию включён **теневой режим**: задачи не создаются. Для демонстрации полного цикла с локальным трекером:

```sh
SHADOW_MODE=0 python3 -m feedback_manager --db data/demo.db serve
```

Откройте тему → «Одобрить тему» → «Подтвердить» → «Создать задачу». Повторный вызов возвращает ту же задачу. Изменение карточки или подтверждений требует повторного одобрения. Неоднозначное сходство создаёт отдельную тему: объединить её может PO. Демо-классификатор использует правила, **это не Qwen**, его результат не доказывает целевые KPI.

## Подключение к контуру

Настройки описаны в [.env.example](.env.example). Значения необходимо передать через окружение процесса; файл `.env` автоматически не загружается. Поддерживаются только HTTPS endpoints из точного `INTERNAL_ALLOWED_HOSTS`; перенаправления и системные HTTP-прокси отключены. Обязателен сетевой egress allowlist на уровне инфраструктуры: приложение не может проверить, действительно ли разрешённый администратором хост принадлежит компании.

* `QWEN_URL` — внутренний chat-completions-совместимый шлюз; имя модели настраивается.
* `MEDIA_URL` — внутренний ASR/VL шлюз с DLP до подачи бинарных данных в модель.
* `SOURCE_URL` — read-only шлюз тикет-системы; опрос раз в минуту.
* `TRACKER_URL` — внутренний шлюз трекера с устойчивым ключом идемпотентности.

Все четыре интеграции имеют явно описанные [контракты](docs/contracts.md). Настоящие endpoints, версии моделей, ACL и продуктовый справочник необходимо согласовать в discovery. Никакие обращения в исходной тикет-системе не изменяются.

Для чистой БД создайте пользователей интерактивно:

```sh
python3 -m feedback_manager user po --name 'Владелец продукта' --role po --products portal
python3 -m feedback_manager user source --name 'Коннектор' --role source --products portal
python3 -m feedback_manager user admin --name 'Администратор' --role admin
python3 -m feedback_manager import docs/source-example.json
python3 -m feedback_manager worker
```

Сервер по умолчанию включает фоновый worker; при отдельном процессе используйте `serve --no-worker`. Одновременно `import` и API источника используют одинаковую дедупликацию. Не запускайте `demo` на БД реального пилота.

## Проверки

```sh
python3 -m unittest discover -s tests -v
node --check feedback_manager/static/app.js
python3 -m feedback_manager.evaluate docs/evaluation-example.jsonl
```

Тесты проверяют E2E, ACL, версии, согласование, split/merge, маскирование, TTL, DLQ, недоступность источника, CSRF и таймаут после создания задачи. CI-конфигурация находится в `.github/workflows/test.yml`; запуск в удалённом CI ещё не подтверждён. Пример evaluation синтетический и проверяет только работу инструмента. Отчёт содержит размер выборки, интервалы Wilson и результаты по продуктам; полнота тем требует отдельной кластерной экспертной разметки.
